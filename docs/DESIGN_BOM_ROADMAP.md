# 2D 设计与算料报价路线图

本文档将当前规划压缩为可执行路线图，按近、中、远三个阶段推进。重点是先打通“画完可算料”，再做“多系列、多窗型、多规则”，最后完善“生产下料、报价策略、协作与扩展能力”。

## 一、目标顺序

```text
先统一设计数据
再让画布直接驱动 BOM
再让系列和窗型配置化
再把报价和下料单独立出来
最后扩展模板、校验、协作和复杂窗型
```

## 二、近程目标：1 个月内

### 目标 1：统一设计数据源

核心任务：

- 定义 `DesignModel`。
- 增加 `DesignComponent`、`ComponentKind`、`OpeningType`、`MaterialRole`。
- 完成 `SketchShape -> DesignModel` 的转换。
- 让保存、加载、CRM 方案都能保留业务字段。

预期结果：

- 画布上画出来的不只是图形，而是可计算的门窗构件。
- 后续 BOM、报价、下料单有统一输入。

### 目标 2：基础 BOM 能从画布生成

核心任务：

- 新增 `computeBomFromDesignModel()`。
- 先支持固定窗、一固定一平开、基础中梃、玻璃、基础五金。
- BOM 面板优先读取画布模型。

预期结果：

- 画完基础窗型后可以自动出材料清单。
- 修改尺寸后清单实时变化。

### 目标 3：设计工具语义化

核心任务：

- 将“矩形”改成更明确的门窗构件工具。
- 先区分外框、固定玻璃、平开扇、中梃。
- 修复快捷键冲突。

预期结果：

- 设计师能按门窗业务对象绘图。
- 工具栏与生产语义一致。

## 三、中程目标：2 到 3 个月

### 目标 4：系列配置化

核心任务：

- 建立 `SeriesCatalog`。
- 配置 75 平开、110 平开、120 推拉样本。
- 型材角色、价格、损耗、五金、玻璃规则全部配置化。

预期结果：

- 同一窗型在不同系列下可自动换算料。
- 系列切换不再依赖硬编码。

### 目标 5：窗型模板化

核心任务：

- 建立 `WindowTemplate`。
- 支持固定窗、一固定一平开、两轨两扇推拉、上悬窗等模板。
- 模板可限制允许的系列。

预期结果：

- 常见窗型一键生成初始结构。
- 设计师主要做微调，而不是从零开始画。

### 目标 6：工艺规则校验

核心任务：

- 新增 `validateDesign()`。
- 校验尺寸、连接关系、系列兼容、五金限制、玻璃限制。
- 错误可定位到构件。

预期结果：

- 不合理设计在报价前就被发现。
- 设计师能快速修正问题。

### 目标 7：报价引擎独立化

核心任务：

- 新增 `QuoteEngine`。
- 支持面积价、材料价、颜色加价、开启扇加价、异形加价、安装运输、折扣。
- 让报价和 BOM 解耦。

预期结果：

- 同一设计可按不同报价策略计算。
- 报价明细可解释。

## 四、远程目标：3 个月以后

### 目标 8：下料单和排料优化

核心任务：

- 新增 `CuttingEngine`。
- 输出逐根型材和切角信息。
- 支持原料长度和余料管理。

预期结果：

- 可以直接给生产使用。
- BOM 和下料单彻底分离。

### 目标 9：复杂窗型扩展

核心任务：

- 扩展悬窗、观景窗、异形窗、组合窗。
- 新增窗型计算器和规则集。

预期结果：

- 新窗型通过配置和局部算法扩展即可支持。
- 不破坏已有基础窗型。

### 目标 10：体验和协作增强

核心任务：

- 模板库面板。
- 材料统计面板。
- 本地自动保存。
- 3D 展示增强。
- 离线草稿能力。
- 方案共享和协作预留。

预期结果：

- 设计、算料、报价、展示、保存形成闭环。
- Web 版体验接近专业设计工具。

当前进度：目标 10 已完成 —— 模板库下拉按窗型类型分组并标注系列兼容性（不兼容禁用）；右侧新增实时「材料统计」面板（构件事务 + 型材/玻璃/五金/辅料项数 + 材料合计金额 + 计价面积）；本地**自动保存**（防抖 0.5s 落盘）+ 启动时草稿恢复提示，CRM 方案保存后自动清除草稿；方案支持 **JSON 导出/导入**（离线备份与协作分享，导出菜单新增两项；「分享」按钮升级为复制完整方案）；3D 预览沿用既有 Three.js 渲染页（含颜色联动）。

## 五、里程碑建议

### Milestone A：能画、能算

包含：

- DesignModel
- 画布转换层
- 基础 BOM
- 工具语义化

验收标准：

- 画完基础窗型后自动出材料清单。

### Milestone B：能分系列、能出报价

包含：

- SeriesCatalog
- WindowTemplate
- validateDesign
- QuoteEngine

验收标准：

- 不同系列和窗型能算出不同材料和价格。

### Milestone C：能给生产

包含：

- CuttingEngine
- 排料优化
- 下料单导出

验收标准：

- 可以直接输出生产侧能用的下料单。

### Milestone D：能扩展

包含：

- 复杂窗型
- 模板库
- 保存恢复
- 3D 与协作增强

验收标准：

- 系统可持续扩展，不会随着系列和窗型增加而失控。

## 六、推荐执行顺序

1. 先做 `DesignModel`。
2. 再做画布到业务模型的转换。
3. 再做基础 BOM 从画布生成。
4. 同时把工具栏改成构件语义。
5. 然后补系列配置。
6. 再补窗型模板和校验。
7. 最后把报价和下料单拆开。

## 七、现实判断

如果目标是让门窗设计真正服务生产，那么最重要的不是把画布做得更花，而是确保每一个设计动作都能落到可计算、可报价、可下料的数据上。

只要这条链路稳定，后面新增 120、110、75 系列，或者新增平开、推拉、悬窗、观景窗，都只是配置和规则扩展，不会变成重构。
